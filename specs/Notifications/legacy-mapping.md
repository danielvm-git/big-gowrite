## Module path
`src/Appwrite/Platform/Modules/Notifications/`

## Purpose
The Notifications module handles in-app/console notifications delivered to Appwrite platform users. Notifications are stored in the platform-level `notifications` collection (not per-project) and currently target only console-channel users (`NOTIFICATION_TYPE_CONSOLE`, `RESOURCE_TYPE_USERS`). The module provides list and update (mark-read) endpoints for authenticated console users, plus a public tracking pixel endpoint (`/v1/notifications/logos/appwrite`) that serves an SVG logo and simultaneously records email open tracking by decoding a signed JWT embedded in the URL.

## Key business rules
- 🟢 List and update endpoints are **console-only**: they check `$project->getId() !== 'console'` and throw `USER_UNAUTHORIZED` for any other project.
- 🟢 List always appends server-side filters: `channel = NOTIFICATION_TYPE_CONSOLE`, `resourceType = RESOURCE_TYPE_USERS`, `resourceId = $user->getId()`.
- 🟢 Update only modifies the `read` boolean field; it uses a sparse document update.
- 🟢 Authorization on update is double-checked: if `getDocument` returns empty, a privileged `skip` query checks existence to distinguish "not found" from "unauthorized".
- 🟢 The logo endpoint (`/v1/notifications/logos/appwrite`) is `scope: public` — no authentication required.
- 🟢 Email open tracking: when a `jwt` query param is present, it is decoded with `HS256` using `_APP_NOTIFICATIONS_TRACKING_SECRET`. The JWT payload must contain `messageId`, `recipientHash`, `channel`, `projectId`, `purpose=notification_track`.
- 🟢 Tracking updates the matched notification: sets `read=true`, records `firstSeen` (on first open only) and `lastSeen` to the current datetime.
- 🟢 Tracking errors are silently swallowed; the SVG logo is always returned regardless of JWT validity.
- 🟢 The SVG logo supports `theme` param (`system`, `light`, `dark`); `system` uses a CSS media query.
- 🟢 The logo response carries `Cache-Control: no-store` to ensure each email open fires a fresh request to the tracking endpoint.
- 🟡 Notifications are created by an external process (likely the messaging/email workers), not by this module.
