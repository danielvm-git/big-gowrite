## Module path
`src/Appwrite/Platform/Modules/Webhooks/`

## Purpose
The Webhooks module provides full CRUD management for project-level webhook configurations. Webhooks are HTTP callbacks that Appwrite fires when platform events occur (e.g., user creation, document update). This module lets developers register, inspect, modify, delete, and regenerate the signing secret for webhooks belonging to a project. All endpoints are project-scoped and inaccessible from the `console` project.

## Key business rules
- 🟢 The `console` project is blocked at the Init hook level — all webhooks endpoints return `GENERAL_ACCESS_FORBIDDEN` for it.
- 🟢 Webhook URL must be a valid HTTP/HTTPS URL pointing to a public domain (validated by `PublicDomain` validator).
- 🟢 If `secret` is not provided on creation or secret rotation, a 128-character hex string is auto-generated via `bin2hex(random_bytes(64))`.
- 🟢 The `signatureKey` field is stripped from the response in both `getWebhook` and `listWebhooks`; it is only returned on `createWebhook` and `updateWebhookSecret`.
- 🟢 Webhooks are scoped to a project via `projectInternalId` (not `projectId`) for performance on indexed queries.
- 🟢 Re-enabling a webhook (setting `enabled=true` on update) resets the `attempts` counter to 0.
- 🟢 After any write operation, the project's cached document is purged (`purgeCachedDocument('projects', ...)`).
- 🟢 The `authUsername`/`authPassword` fields are stored as `httpUser`/`httpPass` internally and mapped back in the response model filter.
- 🟢 The `tls` field is stored as `security` internally and remapped in the response model filter.
- 🟡 Duplicate webhook IDs throw `WEBHOOK_ALREADY_EXISTS`.
- 🟢 Legacy path aliases (`/v1/projects/:projectId/webhooks`) are registered via `httpAlias` for backwards compatibility.
