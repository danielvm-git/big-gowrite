## Module path

## Purpose
The Tokens module manages short-lived, secret-bearing resource tokens that grant public-URL access to protected Appwrite resources. Currently, the only implemented resource type is storage files (`TOKENS_RESOURCE_TYPE_FILES`). A token carries a 128-byte random secret, an optional expiry datetime, and is associated with a bucket+file pair. Tokens are stored in the `resourceTokens` project-level collection and are designed to be embedded as query-string parameters in file URLs, enabling temporary shareable links without requiring full authentication.

## Key business rules
- 🟢 Tokens are linked to a bucket+file pair; `resourceId` stores `bucketId:fileId` and `resourceInternalId` stores the sequence-based compound key.
- 🟢 Token secrets are 128-byte random values stored encrypted in the database (`encrypt` filter on `secret` field).
- 🟢 Creating a token requires either bucket-level UPDATE permission or, when `fileSecurity` is enabled on the bucket, file-level UPDATE permission.
- 🟢 `expire` is optional and must be a future datetime when provided; `null` means the token never expires.
- 🟢 Listing tokens filters by `resourceType = TOKENS_RESOURCE_TYPE_FILES` and the compound `resourceInternalId`.
- 🟡 Only `ADMIN` and `KEY` auth types are allowed on all endpoints (no session/JWT access).
- 🟡 Token access is constrained by the bucket's enabled state; disabled buckets throw `STORAGE_BUCKET_NOT_FOUND` unless the caller is an API key or privileged user.
- 🟢 Abuse-rate limiting is applied on write operations (create, update, delete) using the default write-rate constants.
