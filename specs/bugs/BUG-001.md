# BUG-001 — CI applies only the first database migration

## Symptom

The `test` job in `.github/workflows/ci.yml` runs:

```bash
psql "$GOWRITE_TEST_DATABASE_URL" -f impl/db/migrations/0001_base.sql
```

It never applies `0002_identity.sql`. The `internal/identity` integration tests
(`TestUserCRUD`, `TestSession`, `TestTOTP`, `TestToken`, …) then fail at setup:

```
clean tokens: ERROR: relation "tokens" does not exist (SQLSTATE 42P01)
```

Every migration added after `0001` is silently ignored, so the gate stops
protecting new schema.

## Reproduction

```bash
createdb gowrite_ci_sim
psql "$GOWRITE_TEST_DATABASE_URL" -f impl/db/migrations/0001_base.sql   # only 0001
GOWRITE_TEST_DATABASE_URL=... go -C impl test ./internal/identity/...
```

Observed: 9 identity tests fail with `relation "tokens" does not exist`.

## Root cause

The workflow hard-codes a single migration file instead of applying every file
in `impl/db/migrations/` in lexical order. It was correct when `0001` was the
only migration and was not updated when `0002_identity.sql` landed.

## Fix

- Add `scripts/apply-migrations.sh` that applies every `impl/db/migrations/*.sql`
  in lexical order with `ON_ERROR_STOP=1`.
- Call that script from the CI `test` job.
- Add a regression test that fails if the workflow stops applying all
  migrations or if the migration sequence has a gap.

## Verify

- `go -C impl test ./db/... -run TestMigrations`
- Fresh DB + all migrations + full `go -C impl test ./...` is green.

## Resolution

- Fix commit: `fix(ci): apply every database migration in the test job`.
- `TestCIMigrationStepAppliesAllMigrations` — PASS (was FAIL before the workflow change).
- `TestMigrationsAreContiguous` — PASS.
- Fresh database `gowrite_ci_sim`: `scripts/apply-migrations.sh` applied
  `0001_base.sql` then `0002_identity.sql`; `go -C impl test ./... -count=1`
  passed for all 9 packages (identity 9/9, jobs, auth, crypto, errors, hash,
  permissions, ratelimit).
