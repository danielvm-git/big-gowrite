## 1. Architectural style

**Hybrid Monolith → Modular Monolith with async workers.** The API server runs as a single PHP/Swoole process handling HTTP, but compute‑intensive and external‑facing work is delegated to **14 background workers** via Redis queues. This gives the operational simplicity of a monolith with the scalability and fault isolation of microservice patterns.

**Key principle:** sync API calls return fast; async work (builds, migrations, certificates, email, push, webhooks) happens out-of-band.

| [007](adrs/007-shared-vs-dedicated-tables.md) | DSN pool with shared-table transition | Gradual migration from dedicated DB per project to shared tables |
| [008](adrs/008-estado-terminal-filas.md) | Mandatory terminal state for queue jobs | Messages never stranded in `processing`; applies universally |

## 4. Data model (see [ERD Complete](erd-complete.md))

**Platform DB** (`dbForPlatform` — MongoDB): projects, keys, platforms, installations, repositories, rules, certificates, webhooks, schedules, reports, insights, notifications, vcsComments, devKeys.

**Project DB** (`dbForProject` — MongoDB): users, sessions, identities, targets, tokens, teams, memberships, buckets, files (bucket_{seq}), resourceTokens, functions, deployments, executions, variables, sites, databases, database_{seq}, attributes, indexes, transactions, transactionLogs, migrations, presenceLogs.

**Key relationships:** projects 1─* (everything). users 1─* sessions/identities/tokens/memberships. teams 1─* memberships *─1 users. functions 1─* deployments 1─* executions. buckets 1─* files. databases 1─* collections 1─* attributes/documents/transactions.

## 5. Integration patterns

| Pattern | Mechanism | Modules |
|---------|-----------|---------|
| Event-driven (internal) | Redis pub/sub + Event bus | All → Webhooks, Realtime, Functions |
| Queue-based workers | Redis lists via utopia-php/queue | Builds, Mails, Messaging, Databases, Migrations, Webhooks, Certificates, Deletes |
| VCS webhooks | HTTPS + HMAC validation | VCS → Functions/Sites (deploy) |
| Function execution | Docker socket → Executor container | Functions, Compute |
| OAuth2 | 30+ social providers | Users (identities), VCS (installations) |
| ACME | Let's Encrypt certificate lifecycle | Proxy (rules) → Certificates worker |
| SDK generation | appwrite/sdk-generator from OpenAPI spec | Generated SDKs in `public/` |

## 6. Auth & security layers

1. **Transport:** HTTPS (Traefik TLS) + WSS for realtime.
2. **Auth types:** ADMIN (platform), KEY (project keys + JWT ephemeral), SESSION (cookies), JWT (functions), ORGANIZATION (team scope).
3. **Authorization:** route scopes (`{resource}.{read|write}`) + document ACL (Role::user/team/any/guests/users).
4. **Multi-tenancy:** `projectInternalId` in every data query.
5. **Secrets:** never returned in API responses.
6. **Rate limiting:** utopia-php/abuse; MFA challenges 10/url+user.

## 7. Background workers

14 workers, each `bin/worker-<name>`. All follow terminal-state contract (ADR-008).

| Worker | Queue | Role |
|--------|-------|------|
| Builds | `BuildV1` | Function/site build execution |
| Certificates | `CertificateV1` | TLS certificate lifecycle |
| Databases | `DatabaseV1` | Async schema ops (DDL) |
| Deletes | `DeleteV1` | Cascading cleanup |
| Functions | `FunctionV1` | Scheduled executions |
| Jobs | `JobV1` | Build callback sync (join) |
| Mails | `MailV1` | Email dispatch |
| Messaging | `MessagingV1` | Push/email/SMS campaigns |
| Migrations | `MigrationV1` | Data import execution |
| Notifications | `NotificationV1` | Console notification delivery |
| Screenshots | `ScreenshotV1` | Site screenshot capture |
| Webhooks | `WebhookV1` | Webhook HTTP delivery |
| Stats-Resources | (stats) | Resource usage aggregation |
| Stats-Usage | (stats) | Usage metric aggregation |
