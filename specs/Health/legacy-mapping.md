## Module path
`src/Appwrite/Platform/Modules/Health/`

## Purpose
The Health module provides a comprehensive diagnostic API for Appwrite server administrators. It exposes read-only endpoints that probe each infrastructure component — HTTP layer, database pools, cache (Redis), pub/sub, NTP time sync, SSL certificates, antivirus (ClamAV), geo service, and all background-job queues — returning pass/fail status with latency in milliseconds. Queue endpoints additionally enforce configurable size thresholds, returning an error when a queue backlog exceeds the limit, allowing operators to detect worker stalls before they become user-visible.

## Key business rules
- 🟢 All queue-check endpoints share a `threshold` query param (default: 5000). When `size >= threshold` the endpoint throws `HEALTH_QUEUE_SIZE_EXCEEDED`.
- 🟢 `/v1/health/db` throws only when ALL database pools fail; partial failures also throw (comment notes they wanted partial-failure tolerance but the current code `!empty($failures)` throws on any failure).
- 🟢 `/v1/health/time` connects to `time.google.com:123` via raw UDP socket with a 5-second receive timeout, then rejects if the server-local drift exceeds ±60 seconds.
- 🟢 `/v1/health/certificate` validates that the TLS cert has not already expired (`$sslExpiration < time()`) and throws `HEALTH_CERTIFICATE_EXPIRED` if so.
- 🟢 `/v1/health/anti-virus` reads `_APP_STORAGE_ANTIVIRUS` env var; if `'disabled'` it returns `status=disabled` without trying to reach ClamAV.
- 🟢 `/v1/health/geo` reads `_APP_GEO_ENDPOINT` env var; if empty it immediately throws `GENERAL_SERVER_ERROR`.
- 🟢 `/v1/health/stats` requires scope `root` and has `label('docs', false)` — it is intentionally hidden from SDK docs.
- 🟢 `/v1/health/version` uses scope `public` — accessible without authentication.
- 🟢 `/v1/health/queue/failed/:name` accepts any valid queue name from a WhiteList derived from env vars (falling back to `Event::*_QUEUE_NAME` constants).
