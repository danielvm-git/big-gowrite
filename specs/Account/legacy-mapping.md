## Purpose
The Account module (as currently scoped in this worktree) implements the Multi-Factor Authentication (MFA) subsystem of the Appwrite account API. It covers the full MFA lifecycle: enabling/disabling MFA on a user account, managing TOTP authenticators (create, verify/confirm, delete), managing backup recovery codes (create, get, regenerate), initiating MFA challenges (TOTP, email, phone, recovery code), and completing those challenges to elevate a session's factor set. Broader account features (registration, login, profile, sessions, verifications) are registered elsewhere; this module exclusively handles the `/v1/account/mfa/**` routes.

## Key business rules
- 🟢 Only `TOTP` authenticator type is currently supported; the `type` param is whitelisted to `['totp']`.
- 🟢 Creating a TOTP authenticator when one already exists and is verified throws `USER_AUTHENTICATOR_ALREADY_VERIFIED`. If an unverified authenticator exists, it is deleted and recreated.
- 🟢 Confirming (updating) a TOTP authenticator requires a valid live OTP at confirmation time; success marks `verified = true`, adds `totp` to the session's `factors` array.
- 🟢 Deleting an authenticator also purges the user's cached document (`purgeCachedDocument`).
- 🟢 MFA challenge factors: `email`, `phone`, `totp`, `recovery_code`. Email requires `_APP_SMTP_HOST` to be set and the email to be verified. Phone requires `_APP_SMS_PROVIDER` and a verified phone number.
- 🟢 Recovery-code challenges consume the code on success (remove from `mfaRecoveryCodes` array).
- 🟢 Completing any challenge updates `session.factors` (append the verified factor type, deduplicate) and sets `session.mfaUpdatedAt`.
- 🟢 `updateMFA(true)` recalculates the session's factor set by checking: verified TOTP, verified email, verified phone, and updates `session.factors` accordingly.
- 🟢 `createMFARecoveryCodes` throws `USER_RECOVERY_CODES_ALREADY_EXISTS` if codes already exist; use `updateMFARecoveryCodes` (PATCH) to regenerate.
- 🟢 `getMFARecoveryCodes` and `updateMFARecoveryCodes` are in the `mfaProtected` group (require MFA completion); `deleteMFAAuthenticator` is also `mfaProtected`.
- 🟢 MFA challenge creation is rate-limited: 10 per (url, userId) combination.
- 🟢 Challenge completion is rate-limited: 10 per (url, challengeId) combination.
- 🟡 Multiple SDK Method entries exist per action for deprecation compatibility (camelCase `Mfa` variants deprecated since 1.8.0, replaced by uppercase `MFA` variants).
