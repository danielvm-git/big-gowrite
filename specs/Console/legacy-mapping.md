## Module path
`src/Appwrite/Platform/Modules/Console/`

## Purpose
The Console module serves as the gateway and utility layer for the Appwrite web console. It provides the console's own API endpoints (configuration variables, email templates, OAuth2 provider metadata, API key scopes, resource availability, and the AI assistant proxy) and handles browser-facing concerns: legacy URL redirects to /console, security headers for web views, and the init hooks that guard console-only and web-only route groups.

## Key business rules
- 🟢 The `API` init action runs for all routes in the `console` group and blocks access unless the request is targeting the `console` project (`$project->getId() === 'console'`). This prevents console-internal endpoints from being called under any other project context.
- 🟢 The `Web` init action runs for all routes in the `web` group and injects browser security headers: `X-Frame-Options: SAMEORIGIN`, `X-XSS-Protection`, `X-UA-Compatible`.
- 🟢 All redirect actions share a single base class that preserves the full path, query string, and fragment when mapping to /console.
- 🟢 The AI assistant endpoint is an internal HTTP proxy to `http://appwrite-assistant:3003/v1/models/assistant/prompt`. It streams the SSE response directly to the client using `$response->chunk()`. It is rate-limited to 15 requests per user (`abuse-limit: 15, abuse-key: userId:{userId}`).
- 🟢 `getVariables` collects configuration from environment variables and the database adapter capabilities (relationship support, operator support, spatial support, fulltext wildcard support, etc.) so the frontend can adapt its UI accordingly. It also checks whether VCS, domain forwarding (CNAME/A/AAAA), and the assistant are configured.
- 🟢 `getResource` validates domain availability for custom rules. It enforces: structure restrictions (allowed subdomain depth for sites and functions domains), a deny list (`_APP_CUSTOM_DOMAIN_DENY_LIST`), reserved platform hostnames, and uniqueness in `dbForPlatform.rules`.
- 🟢 `getConsoleEmailTemplate` always returns the Appwrite built-in default template, ignoring any project-level customization. Locale falls back to English when not provided or not recognized.
- 🟡 `listOAuth2Providers` excludes mock providers and disabled providers. Sandbox providers are included.
- 🟢 Scope lists (`listConsoleProjectScopes`, `listConsoleOrganizationScopes`) are purely static — they read from the `projectScopes` and `organizationScopes` config parameters with no database involvement.

## External dependencies (injected)
- `response`, `request` — Utopia HTTP layer
- `platform` — array of platform configuration (hostnames, sitesDomain, functionsDomain, consoleHostname)
- `dbForPlatform` — platform-level database (rules lookup in `getResource`)
- `dbForProject` — project-level database (adapter capability detection in `getVariables`)
- `authorization` — used in `getResource` to skip permissions when checking rule uniqueness
- `vcsProviders` — callable returning configured VCS provider keys
- `project` — current project document (used by the `console` group guard in `API` init)
- `localeCodes` — injected list of valid locale codes for email template locale validation
