## Module path

## Purpose
The Users module provides the administrative surface for managing project users from the server side. It exposes CRUD operations over user accounts, supports importing users with pre-hashed passwords (Bcrypt, MD5, Argon2, SHA, PHPass, Scrypt, Scrypt Modified), and manages every sub-resource attached to a user: sessions, targets (push/email/SMS notification endpoints), JWT tokens, one-time login tokens, memberships, OAuth2 identities, preferences, labels, status flags, multi-factor authentication, and MFA recovery codes. All endpoints require `users.read` or `users.write` scope and are restricted to Admin or API Key auth — end users cannot call these routes directly.

## Key business rules
- 🟢 Email is lower-cased and checked for uniqueness across both `users` and `identities` collections before creation.
- 🟢 If project `auths.personalDataCheck` is enabled, the password must not contain the user's id, email, name, or phone.
- 🟢 Project-level email policy flags (`disposableEmails`, `canonicalEmails`, `freeEmails`, `corporateEmails`) block certain email domains; enforcement is also gated by `plan` capabilities.
- 🟢 Passwords for plain-text imports are hashed with `Utopia\Auth\Proofs\Password` (Argon2id by default); import endpoints accept the already-hashed form and store it verbatim with the corresponding hash name.
- 🟢 Password history is maintained if `auths.passwordHistory > 0`; new passwords are checked against history via hooks.
- 🟢 When a user is created with an email or phone, a corresponding `targets` document is auto-created (providerType = `email` or `sms`).
- 🟢 Admin-created sessions (`createUserSession`) use `SESSION_PROVIDER_SERVER` provider and skip password verification; the secret is generated via `Token` proof, encoded into the `Store`, and returned as an opaque session token.
- 🟢 JWT tokens created via `createUserJWT` are signed with `_APP_OPENSSL_KEY_V1` (HS256) and scoped to the user ID + session ID.
- 🟢 User deletion hard-deletes identities and targets inline; then enqueues a `DELETE_TYPE_DOCUMENT` message for the delete worker to clean up sessions, memberships, logs, files owned by the user.
- 🟢 MFA update stores a boolean `mfa` attribute; MFA authenticator deletion requires verifying the authenticator type matches an enrolled TOTP/email/phone factor.
- 🟡 `listUsers` optimizes target loading: when no `select` query restricts fields, targets are fetched in a single bulk query by `userInternalId` and attached in-memory, avoiding N+1 queries.
- 🟡 Sub-queries for sessions, tokens, authenticators, challenges, and memberships are skipped using `skipFilters()` during the list operation for performance.
