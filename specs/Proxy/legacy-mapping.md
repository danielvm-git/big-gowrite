## Module path
`src/Appwrite/Platform/Modules/Proxy/`

## Purpose
The Proxy module manages custom domain routing rules for Appwrite projects. It allows projects to serve the Appwrite API, a Function execution endpoint, a Site deployment, or a URL redirect under a user-controlled domain. The module handles rule creation with DNS verification, TLS certificate provisioning (via the Certificate publisher), and rule lifecycle management (list, get, delete, retry verification). It is used by both Functions and Sites to expose deployments on branded domains.

## Key business rules
- 🟢 Rule IDs are generated as `md5(strtolower(domain))` when `_APP_RULES_FORMAT=md5` (legacy migration mode), otherwise `ID::unique()`.
- 🟢 Domains that match Appwrite-owned patterns (`_APP_DOMAIN_FUNCTIONS`, `_APP_DOMAIN_SITES`, `_APP_DOMAIN_FUNCTIONS_FALLBACK`) are auto-verified and skip DNS checks (status → `verified`, owner = `'Appwrite'`).
- 🟢 On creation, domain validation fires immediately; if DNS records pass, status advances to `certificate_generating` and a Certificate publish event is enqueued.
- 🟢 The `created` internal status is remapped to `unverified` before returning it to callers for consistency.
- 🟢 Domains on the platform hostname list, `_APP_DOMAIN_SITES`, `_APP_DOMAIN_FUNCTIONS`, and `_APP_CUSTOM_DOMAIN_DENY_LIST` are denied.
- 🟢 Duplicate rules: if the conflicting rule's owning project no longer exists, the orphan is deleted and creation retries.
- 🟢 CAA record check (`_APP_DOMAIN_TARGET_CAA`) gates certificate issuance before CNAME/A/AAAA validation.
- 🟢 CNAME targets differ by resource type: Sites use `_APP_DOMAIN_SITES`, Functions/API use `_APP_DOMAIN_TARGET_CNAME`.
- 🟢 Redirect rules require a parent resource (`site` or `function`) to be specified.
- 🟢 `listRules` and `getRule` hydrate certificate logs and `renewAt` from the associated certificate document.
- 🟢 Deleting a rule enqueues a `DELETE_TYPE_DOCUMENT` message to clean up associated certificates.
- 🟢 `updateRuleVerification` is a no-op if the rule is already `verified` or `certificate_generating`.
