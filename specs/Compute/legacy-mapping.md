## Purpose
The Compute module is a shared infrastructure library — not a standalone API surface — that provides reusable base classes and helpers used by the Functions and Sites modules. It exposes no HTTP routes of its own. Its primary components are: (1) `Base`, a base `Action` class with methods for deploying VCS-backed functions and sites (creating deployment documents, minting preview-domain rules, resolving template refs), (2) `Specification`, an enum-style class listing the available compute size constants (vCPU/memory tiers), and (3) `Validator/Specification`, a validator that filters allowed compute specifications against billing plan limits and environment-variable caps.

## Key business rules
- 🟢 `getDefaultSpecification` returns the lowest allowed specification in the billing plan, or the highest available if no plan is set. When `preferFallback=true` and the plan has no `planKey`, the constant `APP_COMPUTE_SPECIFICATION_DEFAULT` is returned.
- 🟢 `resolveTemplateRef` resolves wildcard tag references (e.g. `0.3.*`) to the highest matching concrete tag by querying the GitHub VCS adapter; falls back to the raw reference on error.
- 🟢 `redeployVcsFunction` creates a `deployments` document with `resourceType='functions'`. For non-template VCS deployments it uses the `Deployments::createFromUrl` service; for template deployments it creates the document directly and enqueues a `BuildMessage` to the builds publisher.
- 🟢 `redeployVcsSite` creates a `deployments` document with `resourceType='sites'` and additionally mints three `rules` documents in `dbForPlatform`: a unique deployment domain, an optional commit-hash-prefixed domain, and a branch-preview domain. Empty-deployment-id manual rules are backfilled via `updateEmptyManualRule`.
- 🟢 `activateBranchPreviewRule` upserts (create-or-update) the branch-preview rule to point to a newly built deployment. It also iterates manual rules pinned to the same branch and updates their `deploymentId`.
- 🟡 Template-based VCS deployments are handled by the Builds worker; plain VCS deployments go through the `Deployments` service directly.
- 🟢 `_APP_RULES_FORMAT=md5` env var triggers legacy MD5-based rule IDs for backward compatibility.
