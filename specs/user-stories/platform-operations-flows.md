## Stories

### US-HLT-01 — Check platform health
**As a** platform operator,
**I want** to probe DB, cache, pubsub, storage, geo, antivirus, NTP, certificates and version,
**so that** I can verify the stack is healthy.
**Priority:** Must · **Unit:** Health (RF-01..RF-11) · **Confidence:** 🟢
**HTTP:** `GET /v1/health` → `get` · `GET /v1/health/{db|cache|pubsub|time|storage|storage/local|anti-virus|geo|certificate|version}` → `get*`

**Acceptance criteria**
- Given a healthy DB pool, When I ping, Then a status object with ping time is returned. (🟢)
- Given a failed dependency, When I probe, Then the check reports the failure. (🟢)
- Given an anonymous caller, When I request version, Then it is public. (🟢)

### US-HLT-02 — Monitor queue sizes and failed jobs
**As a** platform operator,
**I want** to inspect queue sizes and failed-job counts,
**so that** I can detect backlogs.
**Priority:** Must · **Unit:** Health (RF-13, RF-14) · **Confidence:** 🟢
**HTTP:** `GET /v1/health/queue/{queue}` → `getQueue*` · `GET /v1/health/queue/failed/{name}` → `getFailedJobs` · `GET /v1/health/stats` → `getStats`

**Acceptance criteria**
- Given a queue, When I request its size, Then the backlog is returned. (🟢)
- Given a worker, When I request failed jobs, Then the count for that worker is returned. (🟢)
- Given a root caller, When I request stats, Then resource/usage stats are returned. (🟢)

### US-MIG-01 — Run and monitor migrations
**As a** console user,
**I want** to migrate from Appwrite/Firebase/Supabase/NHost and import/export CSV/JSON,
**so that** I can move data into the platform.
**Priority:** Must · **Unit:** Migrations (RF-01..RF-08) · **Confidence:** 🟢
**HTTP:** `POST /v1/migrations/{appwrite|firebase|supabase|nhost}` → `create*Migration` · `GET /v1/migrations/{source}/report` → `get*Report` · `POST /v1/migrations/csv/{exports|imports}` → `createCSVExport` / `createCSVImport` · `POST /v1/migrations/json/{exports|imports}` → `createJSONExport` / `createJSONImport` · `GET/PATCH/DELETE /v1/migrations/{migrationId}` → `getMigration` / `retryMigration` / `deleteMigration`

**Acceptance criteria**
- Given source credentials, When I start a migration, Then the job is created and run. (🟢)
- Given a migration, When I get its report, Then per-resource totals and errors are listed. (🟢)
- Given a failed migration, When I retry it, Then it is re-queued. (🟢)
- Given a CSV/JSON payload, When I import/export, Then data is transformed and staged. (🟢)

### US-PRX-01 — Manage proxy forwarding rules
**As a** console user,
**I want** to create/list/get/delete rules (API, function, site, redirect) and retry verification,
**so that** custom domains route to my resources.
**Priority:** Must · **Unit:** Proxy (RF-01..RF-08) · **Confidence:** 🟢
**HTTP:** `POST /v1/proxy/rules/{api|function|site|redirect}` → `create*Rule` · `GET /v1/proxy/rules` → `listRules` · `GET/DELETE /v1/proxy/rules/{ruleId}` → `getRule` / `deleteRule` · `PATCH /v1/proxy/rules/{ruleId}/status` → `updateRuleVerification`

**Acceptance criteria**
- Given a domain + target resource, When I create a rule, Then the rule is registered and verified asynchronously. (🟢)
- Given an unverified rule, When I retry verification, Then the check re-runs. (🟢)
- Given a rule, When I delete it, Then the domain stops forwarding. (🟢)

### US-AVR-01 — Generate avatars and images
**As a** developer,
**I want** to fetch browser/credit-card/flags/favicon/initials/QR/screenshot images,
**so that** client UI assets are generated server-side.
**Priority:** Should · **Unit:** Avatars (RF-01..RF-08) · **Confidence:** 🟢
**HTTP:** `GET /v1/avatars/{browsers|credit-cards|flags|favicon|image|initials|qr|screenshots}` → `get*` · `GET /v1/cards/cloud{,-back,-og}` → `getCloudCard*`

**Acceptance criteria**
- Given a code, When I request a browser/flag/card icon, Then the PNG is returned. (🟢)
- Given text, When I request initials/QR, Then the generated PNG is returned. (🟢)
- Given a URL, When I request a favicon/screenshot, Then the remote resource is fetched and rendered. (🟢)

### US-ADV-01 — Review advisor reports and insights
**As a** console user,
**I want** to list/get/delete reports and drill into insights,
**so that** I can act on platform recommendations.
**Priority:** Should · **Unit:** Advisor (RF-01..RF-05) · **Confidence:** 🟢
**HTTP:** `GET /v1/reports` → `listReports` · `GET/DELETE /v1/reports/{reportId}` → `getReport` / `deleteReport` · `GET /v1/reports/{reportId}/insights` → `listInsights` · `GET /v1/reports/{reportId}/insights/{insightId}` → `getInsight`

**Acceptance criteria**
- Given a project, When I list reports, Then paginated reports are returned. (🟢)
- Given a report, When I get it, Then its insights are embedded. (🟢)
- Given an insight, When I get it, Then it is scoped to its parent report. (🟢)
