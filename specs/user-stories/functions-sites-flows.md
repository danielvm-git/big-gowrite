## Stories

### US-FN-01 — Create and configure functions
**As a** developer,
**I want** to create, update, delete and link functions to a VCS repository,
**so that** I can run serverless code per project.
**Priority:** Must · **Unit:** Functions (RF-01) · **Confidence:** 🟢
**HTTP:** `POST /v1/functions` → `createFunction` · `GET /v1/functions` → `listFunctions` · `GET/PUT/DELETE /v1/functions/{functionId}` → `getFunction` / `updateFunction` / `deleteFunction`

**Acceptance criteria**
- Given a runtime/entrypoint, When I create a function, Then it is registered for the project. (🟢)
- Given VCS linkage parameters, When I create/update, Then repository+branch are attached. (🟢)
- Given a function, When I delete it, Then its deployments/executions are cleaned up. (🟢)

### US-FN-02 — Deploy code (upload, template, VCS, duplicate) and activate
**As a** developer,
**I want** to upload, list, download, duplicate, delete and activate deployments,
**so that** new code versions are promoted to production.
**Priority:** Must · **Unit:** Functions (RF-02, RF-04, RF-05, RF-06, RF-07, RF-08) · **Confidence:** 🟢
**HTTP:** `POST /v1/functions/{functionId}/deployments` → `createDeployment` (chunked) · `GET /v1/functions/{functionId}/deployments` → `listDeployments` · `GET/DELETE .../deployments/{deploymentId}` → `getDeployment` / `deleteDeployment` · `GET .../deployments/{deploymentId}/download` → `downloadDeployment` · `POST .../deployments/{deploymentId}/duplicate` → `createDuplicateDeployment` · `POST .../deployments/template` → `createTemplateDeployment` · `POST .../deployments/vcs` → `createVcsDeployment` · `PATCH .../deployments/{deploymentId}/status` → `updateDeploymentStatus` · `PATCH /v1/functions/{functionId}/deployment` → `updateFunctionDeployment`

**Acceptance criteria**
- Given a code bundle, When I upload it, Then a build is triggered and a deployment is created. (🟢)
- Given a template id, When I deploy from template, Then the template's repository is used. (🟢)
- Given a deployment, When I update its status, Then the build can be canceled. (🟢)
- Given a deployment id, When I set it as active, Then subsequent executions use it. (🟢)

### US-FN-03 — Execute functions (sync/async) and manage executions
**As a** developer,
**I want** to trigger executions and list/delete execution history,
**so that** code runs on demand or via events.
**Priority:** Must · **Unit:** Functions (RF-09) · **Confidence:** 🟢
**HTTP:** `POST /v1/functions/{functionId}/executions` → `createExecution` · `DELETE /v1/functions/{functionId}/executions/{executionId}` → `deleteExecution`

**Acceptance criteria**
- Given a sync execution, When I invoke, Then the response body/status code are returned inline. (🟢)
- Given an async execution, When I invoke, Then I receive the execution id immediately. (🟢)
- Given an execution, When I delete it, Then its logs/state are removed. (🟢)

### US-FN-04 — Manage environment variables with secret masking
**As a** developer,
**I want** to create/update/delete variables for a function,
**so that** code can read configuration without hardcoding secrets.
**Priority:** Must · **Unit:** Functions (RF-10) · **Confidence:** 🟢
**HTTP:** `POST /v1/functions/{functionId}/variables` → `createVariable` · `GET .../variables` → `listVariables` · `GET/PUT/DELETE .../variables/{variableId}` → `getVariable` / `updateVariable` / `deleteVariable`

**Acceptance criteria**
- Given a key/value, When I create a variable, Then it is available to executions. (🟢)
- Given an existing variable, When I list/get it, Then the value is masked. (🟢)
- Given a variable, When I delete it, Then it disappears from future executions. (🟢)

### US-FN-05 — Discover runtimes, specifications and templates
**As a** developer,
**I want** to list runtimes, compute specifications and deployment templates,
**so that** I choose valid options for functions.
**Priority:** Should · **Unit:** Functions (RF-03, RF-11) + Compute (RF-01, RF-02, RF-06, RF-07) · **Confidence:** 🟢
**HTTP:** `GET /v1/functions/runtimes` → `listRuntimes` · `GET /v1/functions/specifications` → `listSpecifications` · `GET /v1/functions/templates` → `listTemplates` · `GET /v1/functions/templates/{templateId}` → `getTemplate`

**Acceptance criteria**
- Given enabled runtimes, When I list them, Then the available set is returned. (🟢)
- Given a specification id, When I validate against plan/env caps, Then invalid specs are rejected. (🟢)

### US-SITE-01 — Manage static sites and their deployments
**As a** developer,
**I want** to create sites, deploy (upload/template/VCS), activate and manage variables,
**so that** static web apps are hosted per project.
**Priority:** Must · **Unit:** Sites (RF-01..RF-09) · **Confidence:** 🟢
**HTTP:** `POST /v1/sites` → `createSite` · `GET /v1/sites` → `listSites` · `GET/PUT/DELETE /v1/sites/{siteId}` → `getSite` / `updateSite` / `deleteSite` · deployments/variables endpoints mirror Functions

**Acceptance criteria**
- Given a branch, When I create a site, Then it is registered with VCS linkage. (🟢)
- Given a deployment, When I activate it, Then traffic switches to that build. (🟢)
- Given a VCS push event, When the deployment pipeline runs, Then the site is rebuilt and preview rules can be created (Compute helper `activateBranchPreviewRule`). (🟡)
