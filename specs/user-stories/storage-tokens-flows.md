## Stories

### US-STG-01 — Manage storage buckets
**As a** developer,
**I want** to create, configure and delete buckets,
**so that** files are organized under policies (size, extensions, permissions).
**Priority:** Must · **Unit:** Storage (RF-01) · **Confidence:** 🟢
**HTTP:** `POST /v1/storage/buckets` → `createBucket` · `GET /v1/storage/buckets` → `listBuckets` · `GET/PUT/DELETE /v1/storage/buckets/{bucketId}` → `getBucket` / `updateBucket` / `deleteBucket`

**Acceptance criteria**
- Given bucket settings, When I create a bucket, Then constraints (max size, allowed extensions, encryption, antivirus, fileSecurity) are persisted. (🟢)
- Given an enabled bucket, When I update it, Then the settings are replaced. (🟢)
- Given a bucket with files, When I delete it, Then files are scheduled for async cleanup. (🟢)

### US-STG-02 — Upload files (chunked)
**As a** developer,
**I want** to upload files, including large ones in chunks,
**so that** arbitrary-size content can be stored reliably.
**Priority:** Must · **Unit:** Storage (RF-02) · **Confidence:** 🟢
**HTTP:** `POST /v1/storage/buckets/{bucketId}/files` → `createFile`

**Acceptance criteria**
- Given a single request, When I upload a file, Then metadata + the file blob are stored. (🟢)
- Given a chunked upload, When I upload sequential chunks with offsets, Then the file is assembled. (🟢)
- Given an oversized file, When the bucket limit is exceeded, Then the upload is rejected. (🟢)

### US-STG-03 — Get, list and update file metadata
**As a** developer,
**I want** to read and change file metadata,
**so that** I can manage content without downloading it.
**Priority:** Must · **Unit:** Storage (RF-03) · **Confidence:** 🟢
**HTTP:** `GET /v1/storage/buckets/{bucketId}/files` → `listFiles` · `GET /v1/storage/buckets/{bucketId}/files/{fileId}` → `getFile` · `PUT /v1/storage/buckets/{bucketId}/files/{fileId}` → `updateFile`

**Acceptance criteria**
- Given a query, When I list files, Then pagination/filters apply. (🟢)
- Given a file, When I get it, Then metadata (name, mime, size, permissions) is returned. (🟢)
- Given new values, When I update a file, Then metadata is replaced. (🟢)

### US-STG-04 — Download, view and push files
**As a** developer,
**I want** to download/view files (with Range support) and serve push payloads,
**so that** clients can stream or render content.
**Priority:** Must · **Unit:** Storage (RF-05, RF-06, RF-08) · **Confidence:** 🟢
**HTTP:** `GET .../files/{fileId}/download` → `getFileDownload` · `GET .../files/{fileId}/view` → `getFileView` · `GET .../files/{fileId}/push` → `getFileForPush`

**Acceptance criteria**
- Given a file, When I download it, Then it is served as an attachment with content-disposition. (🟢)
- Given a Range header, When I request a partial download/view, Then a 206 with the byte range is returned. (🟢)
- Given a push-enabled file, When I request the push URL, Then a JWT-signed payload for delivery is returned. (🟡)

### US-STG-05 — Preview files with image transforms
**As a** developer,
**I want** to render image previews with width/height/quality/format options,
**so that** clients get optimized thumbnails.
**Priority:** Should · **Unit:** Storage (RF-07) · **Confidence:** 🟢
**HTTP:** `GET .../files/{fileId}/preview` → `getFilePreview`

**Acceptance criteria**
- Given an image file, When I request a preview with transforms, Then the transformed image is returned. (🟢)
- Given a non-image file, When I request a preview, Then a fallback (or error) is produced. (🟡)

### US-TOK-01 — Create a temporary public link to a file
**As a** developer,
**I want** to mint a token for a bucket+file,
**so that** I can share a temporary public URL without exposing full credentials.
**Priority:** Must · **Unit:** Tokens (RF-01) · **Confidence:** 🟢
**HTTP:** `POST /v1/tokens/buckets/{bucketId}/files/{fileId}` → `createFileToken`

**Acceptance criteria**
- Given UPDATE permission (bucket or file-level with fileSecurity), When I create a token, Then a token with a 128-byte encrypted secret and optional expiry is returned. (🟢)
- Given a disabled bucket, When I create a token, Then `STORAGE_BUCKET_NOT_FOUND` is returned (unless privileged caller). (🟡)
- Given no bucket/file permission, When I create a token, Then access is denied. (🟢)

### US-TOK-02 — List, refresh or revoke file tokens
**As a** developer,
**I want** to list tokens for a file, update their expiry and delete them,
**so that** I can audit and revoke shareable links.
**Priority:** Must · **Unit:** Tokens (RF-02..RF-05) · **Confidence:** 🟢
**HTTP:** `GET /v1/tokens/buckets/{bucketId}/files/{fileId}` → `listFileTokens` · `GET /v1/tokens/{tokenId}` → `getToken` · `PATCH /v1/tokens/{tokenId}` → `updateToken` · `DELETE /v1/tokens/{tokenId}` → `deleteToken`

**Acceptance criteria**
- Given a file, When I list tokens, Then only `resourceType=files` tokens for that compound key are returned. (🟢)
- Given a token, When I update expiry, Then only a future datetime (or null) is accepted. (🟢)
- Given a token, When I delete it, Then the shareable link is immediately invalidated. (🟢)
