## Stories

### US-VCS-01 — Connect a provider via OAuth
**As a** developer,
**I want** to authorize the app with GitHub/GitLab/Gitea,
**so that** repositories can be read and deployed automatically.
**Priority:** Must · **Unit:** VCS (RF-01) · **Confidence:** 🟢
**HTTP:** `GET /v1/vcs/{provider}/authorize` → `getVCS*Authorize` · `GET /v1/vcs/{provider}/callback` → `getVCS*Callback`

**Acceptance criteria**
- Given a provider configured in the project, When I start authorization, Then an OAuth redirect URL is returned. (🟢)
- Given a valid code, When the callback completes, Then the installation/connection is persisted. (🟢)
- Given a denied/invalid grant, When the callback completes, Then an error is surfaced. (🟢)

### US-VCS-02 — Manage installations
**As a** developer,
**I want** to list, get and delete provider installations,
**so that** I control which orgs/repos are connected.
**Priority:** Must · **Unit:** VCS (RF-02) · **Confidence:** 🟢
**HTTP:** `GET /v1/vcs/installations` → `listInstallations` · `GET /v1/vcs/installations/{installationId}` → `getInstallation` · `DELETE /v1/vcs/installations/{installationId}` → `deleteInstallation`

**Acceptance criteria**
- Given a project, When I list installations, Then only that project's connections are returned. (🟢)
- Given an installation, When I delete it, Then the OAuth linkage is revoked and cached data cleared. (🟢)

### US-VCS-03 — Browse provider repositories, branches and contents
**As a** developer,
**I want** to list repos, branches and read file contents,
**so that** I can pick a repo for a function/site and inspect its files.
**Priority:** Must · **Unit:** VCS (RF-03) · **Confidence:** 🟢
**HTTP:** `GET /v1/vcs/{provider}/installations/{installationId}/providerRepositories` → `listRepositories` · `GET .../providerRepositories/{providerRepositoryId}` → `getRepository` · `GET .../providerRepositories/{providerRepositoryId}/branches` → `listRepositoryBranches` · `GET .../providerRepositories/{providerRepositoryId}/contents` → `getRepositoryContents` · `GET /v1/vcs/installations/{installationId}/namespaces` → `listNamespaces`

**Acceptance criteria**
- Given an installation, When I list repositories, Then paginated provider repos are returned. (🟢)
- Given a repo, When I list branches or read contents, Then the provider API result is proxied. (🟢)
- Given an uninstalled repo, When I list, Then `installed=false` is flagged. (🟢)

### US-VCS-04 — Create an internal repository with auto-detection
**As a** developer,
**I want** to attach a provider repository and run detection,
**so that** functions/sites can deploy from it.
**Priority:** Must · **Unit:** VCS (RF-04) · **Confidence:** 🟢
**HTTP:** `POST /v1/vcs/{provider}/installations/{installationId}/providerRepositories` → `createRepository` · `POST /v1/vcs/{provider}/installations/{installationId}/detections` → `createRepositoryDetection`

**Acceptance criteria**
- Given a provider repo, When I create a repository, Then an internal repository record is created. (🟢)
- Given a repository, When I request detection, Then the runtime/framework is inferred from its contents. (🟢)

### US-VCS-05 — Ingest provider webhooks (push, PR, installation)
**As a** developer,
**I want** the provider's events delivered to our endpoints,
**so that** pushes trigger builds and installation changes stay in sync.
**Priority:** Must · **Unit:** VCS (RF-05) · **Confidence:** 🟢
**HTTP:** `POST /v1/vcs/{provider}/events` → `createVCS*Event`

**Acceptance criteria**
- Given a signed push event, When it is delivered, Then the matching repos trigger deployments. (🟢)
- Given an installation event, When delivered, Then installations are created/updated/deleted accordingly. (🟢)
- Given an invalid signature, When delivered, Then the event is rejected. (🟡)

### US-VCS-06 — Authorize external (fork) pull requests
**As a** developer,
**I want** to approve/reject PRs from forks/external contributors,
**so that** untrusted code is gated.
**Priority:** Should · **Unit:** VCS (RF-06) · **Confidence:** 🟡
**HTTP:** `PATCH /v1/vcs/{provider}/installations/{installationId}/repositories/{repositoryId}` → `updateExternalDeployment`

**Acceptance criteria**
- Given a fork PR event, When authorization is requested, Then the external deployment status is updated. (🟡)
- Given a rejected PR, When builds are scheduled, Then the rejected repo is skipped. (🟡)
