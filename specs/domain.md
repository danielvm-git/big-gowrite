## 1. Glossário de domínio

| Termo | Definição |
|-------|-----------|
| **Projeto** | Unidade raiz de isolamento multi-tenant. Dono = `teamInternalId`. Todo recurso herda o `projectInternalId` (scoping anti-vazamento). |
| **ProjectInternalId** | Identificador interno sequencial do projeto usado em coleções de dados e chaves de rate-limit. |
| **Key** | Credencial de API: padrão (persistida, scopes, expiry, `secretHash`) ou **efêmera** (JWT HS256, não persistida). |
| **Scope** | Permissão de API `{resource}.{read\|write}`; especiais: `account`, `public`, `home`, `root`, `assistant.read`. |
| **Rule** | Rota de domínio customizado (api/function/site/redirect) com verificação de DNS e TLS. |
| **Deployment** | Bundle de código de function/site; `building` → `ready`/`failed`. |
| **Execution** | Execução de function (sync/async/scheduled); exige deployment `ready` (`BUILD_NOT_READY`). |
| **Authenticator / Challenge** | Credencial TOTP de MFA confirmada por OTP; desafio com rate-limit e expiração. |
| **Presence** | Estado de presença em tempo real (`presenceLogs`), expiry default 15min. |
| **ResourceToken** | Token curto para acesso público por URL a arquivos (`resourceId = bucketId:fileId`). |
| **Onboarding** | Estágios de setup do projeto (skip rastreado por ator; persistido após métricas de uso). |
| **Schedule** | Job CRON (function/execution/message). |
| **VCS Installation** | Vínculo do projeto com provedor VCS (GitHub App / GitLab/Gitea OAuth2). |
| **Preview Rule** | Rule auto-criada (`owner=Appwrite`) para preview de site sob `sitesDomain`. |
| **Insight/Report (Advisor)** | Resultado de análise automatizada (Lighthouse / database-analyzer) com severidade e CTA. |
| **Membership** | Vínculo user↔team com `roles[]` (string arbitrária, máx 32 chars; default `owner`). |
| **Dev Key** | Credencial legada que "bypassa rate limits e melhora logs" — **deprecated** (`DEV_KEY_GONE`). |

## 2. Regras de domínio consolidadas

### 2.1 Auth & identidade
- 🟢 Unicidade de e-mail vale **entre `users` e `identities`** (OAuth2) — não apenas dentro de users.
- 🟢 Autenticador TOTP verificado não pode ser recriado (409) enquanto existir.
- 🟢 Desafios MFA têm rate-limit de **10 por url+user** e **10 por url+challengeId**.
- 🟢 Sessions criadas por admin usam `SESSION_PROVIDER_SERVER` e **pulam verificação de senha**.
- 🟢 Fatores MFA confirmados são persistidos (deduplicados) na sessão; alternar MFA recalcula `factors`.
- 🟢 Códigos de recuperação: gerados uma vez no create, regenerados no update, armazenados **hasheados**.
- 🟡 Expiração de senha/histórico controlada por `auths.passwordHistory` do projeto.
- 🟡 E-mail sujeito a gates de política: disposable/canonical/free/corporate + `personalDataCheck`.
- 🟡 Auth via header `X-Appwrite-Organization` (ORGANIZATION) escopa ao time mas **não carrega plataforma** — a rota ainda declara ADMIN/KEY/etc.

### 2.2 Teams & membros
- 🟢 Role de time é **string arbitrária** (qualquer valor ≤32 chars), default `owner` no create.
- 🟢 Deve existir **pelo menos um owner** — downgrade/remoção do último owner → `MEMBERSHIP_DOWNGRADE_PROHIBITED`.
- 🟢 Invite pode criar **usuário stub** quando não há match por email/SMS/userId.
- 🟢 Confirm do invite valida o secret (`proofForToken`) e **cria sessão** para convidado não logado.
- 🟢 Status da membership é **derivado** dos timestamps `invited`/`joined` (não é campo de estado).
- 🟢 `membershipsPrivacy` controla quais campos da membership ficam expostos.
- 🟢 Permissões de documento por time usam `Role::team($teamId, 'owner')` etc.

### 2.3 Compute (functions/sites)
- 🟢 Execução/criação exige deployment `ready` → `BUILD_NOT_READY` caso contrário.
- 🟢 Cancelamento de build bloqueado quando deployment `ready`/`failed` → `BUILD_ALREADY_COMPLETED`.
- 🟢 Ativação de deployment é **escopada à function** dona (fix: `reject activating a deployment from another function`).
- 🟢 Variável secreta **não pode ser rebaixada** para pública.
- 🟢 Mudança de variáveis marca function/site `live=false` (rebuild obrigatório).
- 🟢 Erros internos de build **mascarados** dos logs visíveis ao usuário.
- 🟢 Execution síncrona: status por HTTP statusCode (≥500 → `failed`).
- 🟡 Templates de função pinned a fontes releaseadas.

### 2.4 Storage
- 🟢 Upload em chunks (Content-Range) com distributed lock; concorrência → `LockContention`.
- 🟢 Compressão (gz/zstd) + criptografia (AES-128-GCM) no **finalize** apenas se `sizeOriginal ≤ buffer`.
- 🟢 Scan ClamAV com modos disabled/enabled/restricted.
- 🟢 `fileSecurity` vs permissões bucket-level; previews via Imagick; download/view com HTTP Range.
- 🟢 Endpoint push protegido por JWT (HS256, 1h).
- 🟡 Headers de cache via `Storage/Config/CacheControl`.

### 2.5 Databases
- 🟢 Operações de schema são **assíncronas** (publisher → worker → DDL → flags de status).
- 🟢 Transações usam **lock otimista** (`version`): staging multi-coleção, cheque de versão, commit atômico, rollback via publisher de deletes.
- 🟢 Atributos string com `encrypt` são criptografados na persistência.
- 🟢 Relacionamentos bidirecionais **espelhados pelo worker**.
- 🟢 Embeddings fora do namespace vectorsdb (`refactor: move embeddings out of vectorsdb namespace`).
- 🟡 Listagem VectorsDB voltou para **GET** (revert de POST body) — consistência de API.

### 2.6 Proxy & domínios
- 🟢 Status legado `created` é **renomeado para `unverified`** nas leituras (compatibilidade).
- 🟢 Re-verificação de rule bloqueada quando `verified`/`certificate_generating`.
- 🟢 Gate CAA antes de emissão TLS; alvos CNAME variam por resourceType.
- 🟢 Domínios de propriedade da Appwrite auto-verificados; regras órfãs limpas em conflito.
- 🟢 `md5(domain)` como id de rule legado (TODO de migração 1.7.x ainda presente nas rotas).

### 2.7 Migrações
- 🟢 Retry de migração **apenas quando `failed`** (Update valida `status !== 'failed'`).
- 🟢 Todos os providers criam com `status=pending`; política `onDuplicate` fail/skip/overwrite.
- 🟢 Export CSV/JSON grava no bucket interno + notificação por e-mail opcional.
- 🟢 Relatórios de provedor conectam **ao vivo** no request (credenciais validadas na hora).

### 2.8 Presença
- 🟢 Expiry default 15min, máximo 30 dias, soft-expire na leitura.
- 🟢 Cache de lista TTL com header `X-Appwrite-Cache`; purge invalida.
- 🟢 Escrita de `userId` restrita a key/privilegiados (não-cliente).

### 2.9 VCS
- 🟢 Webhooks validam assinatura (403 em mismatch); pushes de bot-email ignorados.
- 🟢 `state` do callback assinado com HMAC.
- 🟢 Deploy de fork externo exige autorização explícita.
- 🟢 Comentários de status com lock otimista; fan-out de deploy multi-repo/project.

### 2.10 Webhooks & notificações
- 🟢 `signatureKey` **nunca retornado** em leituras; apenas no create/rotação.
- 🟢 Re-enable de webhook reseta `attempts`.
- 🟢 Projeto console bloqueado para webhooks; pixel de tracking JWT HS256 com erros silenciados.

## 3. Regras transversais de segurança

- 🟢 Scoping multi-tenant obrigatório via `projectInternalId` em todas as consultas.
- 🟢 Secrets nunca retornados em leituras (OAuth2, webhooks, variables, keys, tokens).
- 🟢 Proteção SSRF no Avatars (allowlist de hostnames, redirects limitados).
- 🟢 Workers/rotas privilegiadas usam `authorization->skip()` de forma controlada.
- 🟢 Lock de escrita de plataforma reintroduzido (`Reintroduce platform write locking`).
