## Module path
`src/Appwrite/Platform/Modules/Project/`

## Purpose
The Project module manages the configuration and lifecycle of a single Appwrite project. It provides HTTP endpoints for reading and deleting a project, managing API keys (standard and ephemeral JWT-based), project-level environment variables, client platform registrations (web, Apple, Android, Windows, Linux), OAuth2 provider credentials, email templates, SMTP configuration, security and auth policies, authentication method toggles, protocol/service toggles, mock phone numbers for OTP testing, and project labels. All endpoints operate in the context of the current project (resolved via an `Init` hook) and write to either `dbForPlatform` (keys, platforms, OAuth2, SMTP) or `dbForProject` (variables).

## Workers & Tasks
None. The Project module has no Workers/ or Tasks/ subdirectories. Deleting a project dispatches to the shared Deletes worker via `publisherForDeletes`.

## Key business rules
- 🟢 The `Init` hook blocks any request where the resolved project is the `console` meta-project or where the project document is empty.
- 🟢 Standard API keys store the secret as `API_KEY_STANDARD_` prefix + 256 bytes of hex-encoded random data. Ephemeral keys store a signed HS256 JWT as `API_KEY_EPHEMERAL_` prefix.
- 🟢 Ephemeral keys are not persisted in the database; their `Document` is built in memory and only the JWT secret is returned to the caller.
- 🟢 A key's `resourceType` must be `'projects'` and its `resourceInternalId` must match `$project->getSequence()` for all key CRUD operations (ownership enforcement).
- 🟢 After any key write, the project document cache is purged (`purgeCachedDocument('projects', ...)`).
- 🟢 Creating or updating a project variable marks all `functions` and `sites` documents in `dbForProject` as `live = false`, forcing a rebuild.
- 🟢 Project variables have `resourceType = 'project'` (singular). Key resources use `resourceType = 'projects'` (plural). Platforms use `projectInternalId`.
- 🟢 When updating SMTP config: if `enabled=true` (or not explicitly set), the endpoint attempts an actual SMTP connection (`PHPMailer::SmtpConnect`) and will throw if the connection fails while `enabled=true`. If the caller sets `enabled=null` and connection succeeds, SMTP is auto-enabled.
- 🟢 Email templates can only be updated when custom SMTP is already enabled on the project.
- 🟢 OAuth2 provider credentials are stored in the `oAuthProviders` map on the project document: `{providerId}Appid`, `{providerId}Secret`, `{providerId}Enabled`. The secret field is always returned empty on reads.
- 🟢 Enabling an OAuth2 provider triggers `verifyCredentials()` on the provider class if the method exists, and throws if credentials fail.
- 🟢 Mock phones are stored as an array in `project.auths.mockNumbers`. The list is capped at `APP_LIMIT_COUNT`. Duplicate phone numbers are rejected.
- 🟢 Policies are virtual documents synthesized from `project.auths.*` attributes rather than stored as separate DB documents.
- 🟡 Platform type backwards compatibility: the old `/v1/projects/:projectId/platforms` `POST` accepted a `type` field with legacy values (`flutter-android`, `react-native-ios`, etc.). The new API has separate paths per platform type. The Web platform's `Create.php` contains the mapping.
- 🟢 Variables support a `secret` flag. A secret variable cannot be downgraded to non-secret (`VARIABLE_CANNOT_UNSET_SECRET` error).
- 🟢 Project deletion: the project document is deleted from `dbForPlatform` then a `DELETE_TYPE_DOCUMENT` message is enqueued to the deletes worker for async cleanup.

## External dependencies (injected)
- `dbForPlatform` — platform-level DB (projects, keys, platforms, OAuth2)
- `dbForProject` — project-level DB (variables, functions, sites)
- `response` — Utopia HTTP response
- `request` — Utopia HTTP request (used in platform create for backwards compat)
- `project` — injected current project Document
- `authorization` — Utopia Authorization (all platform DB writes use `->skip()`)
- `queueForEvents` — event queue (keys, platforms, OAuth2, variables)
- `publisherForDeletes` — delete publisher (project deletion cleanup)
- `publisherForMails` — mail publisher (SMTP test)
- `platform` — platform config array (used in SMTP test email variables)
- `localeCodes` — list of valid locale codes (injected into template endpoints)
