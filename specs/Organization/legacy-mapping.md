## Module path

## Purpose
The Organization module provides team-scoped project management. It exposes CRUD endpoints for Appwrite projects under the `/v1/organization/projects` path, where access is always bound to the calling team (injected as `$team`). It handles project creation (including provisioning a new database namespace or joining a shared table, setting up audit schema, and bootstrapping collection schemas), project listing filtered by team, and project retrieval, update, and deletion. Deletion enqueues an asynchronous cleanup job. This module supports an `ORGANIZATION` auth type alongside the standard `ADMIN` and `KEY` types.

## Key business rules
- 🟢 All endpoints are gated by the Init hook which rejects requests if `$team` is empty.
- 🟢 `projectId = 'console'` is reserved and rejected with `PROJECT_RESERVED_PROJECT`.
- 🟢 Region selection: if `_APP_PROJECT_REGIONS` is set, only listed regions are allowed. If the selected region is not `default`, database DSN candidates are filtered from `_APP_DATABASE_KEYS` to those containing the region string.
- 🟢 Database assignment: a random DSN is chosen from the region-filtered pool unless `_APP_DATABASE_OVERRIDE` is set.
- 🟢 Shared table support: if the chosen DSN is listed in `_APP_DATABASE_SHARED_TABLES`, the project joins a shared schema (`appwrite`) under the configured `_APP_DATABASE_SHARED_NAMESPACE`, no per-project database is created.
- 🟢 Project-table mode: when not on shared tables, a new database namespace (`_` + project sequence) is created, audit schema is set up, and all `projects` collections from config are bootstrapped.
- 🟢 All auth methods are seeded on project creation from the `auth` config parameter.
- 🟢 Access control: `Get`, `Update`, and `Delete` verify that `project.teamInternalId === team.getSequence()` before acting; a mismatch returns `PROJECT_NOT_FOUND`.
- 🟢 Project deletion enqueues a `DELETE_TYPE_DOCUMENT` message via `publisherForDeletes` for async cleanup.
- 🟢 After project creation, a `hooks->trigger('afterProjectCreation', ...)` call is fired to support migration mirroring.
- 🟡 `XList` supports `select` queries and skips expensive sub-query filters for unselected attributes via `skipFilters`.
- 🟢 Default auth configuration includes session duration, password history, MFA settings, session alerts, etc.
