## Module path
`src/Appwrite/Platform/Modules/Projects/`

## Purpose
The Projects module manages the lifecycle of Appwrite projects on the platform layer. It handles project creation (including database provisioning, collection scaffolding, and audit schema setup), metadata updates, team ownership transfers, developer keys (now deprecated/tombstoned), CRON schedules linked to resources such as functions and messages, and onboarding stage tracking. Projects are top-level entities stored in the platform-wide database (`dbForPlatform`), not in per-project databases.

## Key business rules
- 🟢 Project ID `console` is reserved and cannot be used — throws `PROJECT_RESERVED_PROJECT`.
- 🟢 The owning team must exist before a project can be created — throws `TEAM_NOT_FOUND`.
- 🟢 Region must be in the configured allowed list (`_APP_PROJECT_REGIONS`) when that list is non-empty.
- 🟢 Database DSN is selected at project creation time: filtered by region if non-default, randomised from the pool, overridable via `_APP_DATABASE_OVERRIDE`; stored on the project document.
- 🟢 Shared-table projects share the `appwrite` schema and namespace; dedicated-table projects get their own namespace (`_<internalId>`) and have their collections and audit schema initialised on creation.
- 🟢 `createDevKey` always throws `DEV_KEY_GONE` — the endpoint is tombstoned and kept only for backwards-compatible error messaging.
- 🟢 Dev key operations verify `projectInternalId` matches before acting, preventing cross-project key access.
- 🟢 Schedule creation validates that the referenced resource (function/execution/message) exists in the project DB before creating the schedule document in the platform DB.
- 🟢 `listSchedules` filters by both `projectId` and `projectInternalId` (allowing null for legacy records).
- 🟢 Onboarding stages come from the `onboarding` config; a completed stage cannot be overwritten as skipped.
- 🟢 `updateStage` resolves actor type (key-account, key-organization, key-project, admin, user, guest) to tag who skipped the stage.
- 🟢 On team transfer (`updateProjectTeam`), permissions are propagated to all installations, repositories, and VCS comments belonging to the project.
- 🟡 Project status defaults to `PROJECT_STATUS_ACTIVE` at creation; status field exists but no endpoint to change it is present in this module.
- 🟢 A post-creation hook `afterProjectCreation` is triggered to support instant project mirroring during migrations.
